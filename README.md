# Vault3

Децентрализованное файловое хранилище со сквозным шифрованием.

**Демо:** https://vault3-ashy.vercel.app/
**Смарт-контракт:** [0x6B8Add53Dd53938ea1d42316CFA80F6daf22ae44](https://amoy.polygonscan.com/address/0x6B8Add53Dd53938ea1d42316CFA80F6daf22ae44)

## О проекте

Vault3 — приложение для хранения файлов на базе EVM-совместимого блокчейна и протокола IPFS. Файлы шифруются в браузере пользователя до отправки, хранятся в распределённой сети IPFS, а метаданные записываются в смарт-контракт на блокчейне.

Архитектурный паттерн: блокчейн хранит метаданные и контроль доступа, IPFS — содержимое файлов, клиент — ключи шифрования.

## Возможности

- Шифрование AES-256-GCM в браузере (Web Crypto API)
- Распределённое хранение в IPFS через сервис Pinata
- Метаданные и контроль владения через смарт-контракт на Polygon Amoy
- Аутентификация через кошелёк MetaMask, без паролей и регистраций
- Загрузка, скачивание, просмотр, удаление и поиск файлов

## Подготовка кошелька

Перед использованием приложения нужно настроить MetaMask. Это разовая процедура.

### 1. Установка MetaMask

Скачайте расширение для вашего браузера с официального сайта: https://metamask.io/download/

Поддерживаются: Chrome, Firefox, Brave, Edge.

После установки откройте расширение и создайте новый кошелёк. Запишите seed-фразу из 12 слов на бумаге и храните в безопасном месте — это единственный способ восстановить доступ.

### 2. Добавление сети Polygon Amoy

По умолчанию MetaMask работает только с основной сетью Ethereum. Нужно добавить тестовую сеть Polygon Amoy.

В MetaMask: нажмите на название текущей сети сверху → включите переключатель «Show test networks» → выберите «Add a custom network» (или «Add network manually»).

Заполните поля:

| Поле | Значение |
|------|----------|
| Network name | Polygon Amoy |
| RPC URL | https://rpc-amoy.polygon.technology |
| Chain ID | 80002 |
| Currency symbol | POL |
| Block explorer URL | https://amoy.polygonscan.com |

Сохраните и переключитесь на эту сеть. Приложение само попросит переключиться, если вы будете в другой сети.

### 3. Получение тестовых токенов POL

Для оплаты газа за транзакции (загрузка и удаление файлов) нужны тестовые токены POL. В тестовой сети они бесплатные и выдаются через faucet — специальный сервис-кран.

Скопируйте свой адрес кошелька в MetaMask (клик по адресу сверху копирует его), затем перейдите на один из faucet'ов:

- https://faucet.polygon.technology/
- https://faucet.quicknode.com/polygon/amoy
- https://cloud.google.com/application/web3/faucet/polygon/amoy

Вставьте адрес, выберите сеть Polygon Amoy и токен POL. Через 30–60 секунд токены появятся в кошельке. Faucet выдаёт около 0.1 POL раз в 24 часа; этого хватит на десятки операций в приложении.

### 4. Использование

Откройте https://vault3-ashy.vercel.app/, нажмите «Подключить кошелёк», подтвердите подключение в MetaMask — после этого приложение готово к работе.

Каждая операция с файлами (загрузка, удаление) требует подтверждения транзакции в MetaMask и стоит около 0.01 POL.

## Запуск локально

Требования: Node.js 18+, MetaMask, тестовые токены POL в сети Polygon Amoy.

```bash
git clone https://github.com/viperking21980/vault3.git
cd vault3/frontend
npm install
cp .env.example .env
# заполнить .env (см. ниже)
npm run dev
```

Откройте http://localhost:5173.

## Переменные окружения

В `frontend/.env`:

```
VITE_CONTRACT_ADDRESS=0x6B8Add53Dd53938ea1d42316CFA80F6daf22ae44
VITE_ALCHEMY_URL=https://polygon-amoy.g.alchemy.com/v2/YOUR_KEY
VITE_PINATA_JWT=YOUR_PINATA_JWT
```

`VITE_ALCHEMY_URL` — RPC-эндпоинт от Alchemy для Polygon Amoy.
`VITE_PINATA_JWT` — JWT-токен из Pinata с правом загрузки файлов.

Можно использовать уже развёрнутый адрес контракта или развернуть собственный.

## Развёртывание собственного смарт-контракта

```bash
cd contracts
npm install
cp .env.example .env
# в .env указать ALCHEMY_URL и PRIVATE_KEY кошелька с тестовыми POL
npx hardhat compile
npx hardhat run scripts/deploy.ts --network amoy
```

После развёртывания в консоль выводится адрес контракта. Используйте его в `frontend/.env`.

## Как работает шифрование

1. Пользователь выбирает файл и вводит пароль
2. Из пароля выводится ключ AES-256 через PBKDF2 (100 000 итераций, случайная соль)
3. Файл шифруется алгоритмом AES-256-GCM со случайным IV
4. Результат `salt | iv | ciphertext` загружается в IPFS, возвращается CID
5. CID и метаданные (имя, размер, тип) записываются в смарт-контракт

Пароль не покидает браузер. Pinata видит только зашифрованные байты. Блокчейн видит только CID. Без пароля содержимое файла нечитаемо.

## Известные ограничения

- Прототип не поддерживает шеринг файлов между пользователями
- Восстановление пароля не предусмотрено
- Используется один pinning-провайдер; для отказоустойчивости нужно несколько сервисов или собственный IPFS-узел
- Нет версионирования файлов
- Работа в тестовой сети, без реальной экономической модели
